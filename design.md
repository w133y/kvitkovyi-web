# Дизайн-система «Квітковий»

Довідник по візуальній мові сайту: кольори, типографіка, відступи, компоненти. Джерело істини — `app/globals.css`; цей файл пояснює *чому* так, а не дублює кожне правило.

## Тема

Сайт **тільки темний** — світлу тему свідомо прибрали (була реалізована й видалена). `:root` у `app/globals.css` містить кольорові токени як CSS-змінні заради єдиного джерела правди (замість ~250 копій одних і тих самих сірих), а не заради перемикання тем.

### Панелі («modern panel»)

Уведено для `/wiki` та `/leaderboard`, потім розкотили на всі великі структурні картки (`.box`, `.box2`, `.box3`, `.product-card`, картки профілю, галереї, адмінки тощо):

| Змінна | Значення |
|---|---|
| `--panel-bg` | `rgba(255, 255, 255, 0.04)` |
| `--panel-bg-raised` | `rgba(255, 255, 255, 0.06)` |
| `--panel-border` | `1px solid var(--border-soft-color)` |
| `--panel-radius` | `20px` |
| `--panel-radius-sm` | `16px` |
| `--panel-row-bg` | `#2d2d2d` — рядок-елемент *усередині* вже прозорої панелі (щоб не зливався) |
| `--panel-row-border` | `1px solid rgba(255, 255, 255, 0.06)` |

**Свідомо не застосовується** до полів вводу, дрібних кнопок-іконок і випадних списків — вони не «картки» в цьому сенсі й краще виглядають у своєму більш «втопленому» вигляді (див. нижче).

### «Втоплені» елементи (форми, дропдауни, модалки)

Ці елементи мають фіксований темний фон завжди, незалежно від контексту — і тому їхній текст теж фіксований (`white`/`rgb(190,190,190)`), а не токен-залежний, бо навколишній фон ніколи не змінюється:

| Змінна | Значення | Де |
|---|---|---|
| `--input-bg` | `rgba(0, 0, 0, 0.3)` | Втоплені `<pre>`, службові блоки |
| фон полів (літерал) | `rgb(45, 45, 45)` / `rgb(35, 35, 35)` | `input`, `select`, `textarea`, дропдауни, модалки |

> Якщо додаєш нове поле вводу чи випадний список — фон і текст лишай літералами (`white`, `rgb(190, 190, 190)` тощо), **не** токенами `--text-*`. Токени існують для елементів на фоні сторінки/панелі; втоплені елементи навмисно поза цією системою.

## Типографіка

- **Minecraft** (`/fonts/Minecraft.ttf`) — заголовки, кнопки, усе, що має «ігровий» характер: навігація, `h1`–`h3` за замовчуванням, кнопки.
- **Ubuntu Sans** (Google Fonts) — заголовки секцій (`body h2`), деякі картки; більш читабельний за Minecraft у довших рядках.
- Основний текст (`body p`) — системний sans-serif через `font-family: "Ubuntu Sans", sans-serif`.

## Брейкпоінти

| Ширина | Що змінюється |
|---|---|
| `≤ 1500px` (і `> 1024px`) | Плашка навігації вирівнюється по лівому краю замість центрування — на «планшетних» ширинах їй бракує місця по центру поруч з віджетом профілю |
| `≤ 1200px` | Логотип у хедері збільшується (`width: 60%`) |
| `≤ 1024px` | Плашка навігації ховається, з'являється гамбургер; профіль переїжджає в мобільне меню |
| `≤ 768px` | Логотип `75%`; секційні відступи переходять на мобільні токени |
| `≤ 480px` | Логотип `88%`; заголовки `.leaderboard-top-title` зменшуються |

**Важливо:** якщо додаєш `max-width`/`width` правило для елемента, який уже має явний `width` у базовому селекторі — `max-width` у медіа-запиті нічого не зробить, поки він більший за вже вказаний `width`. Змінюй саме `width` (див. історію бага з логотипом на мобільних).

## Компоненти

### Кнопки

- **`.custom-button:first-child`** — суцільна CTA-кнопка, `var(--brand-gradient)`, білий/темний текст (`color: var(--text-primary)`).
- **`.custom-button:last-child`** — контурна кнопка, `border: 4px solid var(--text-primary)`, прозорий фон.
- **`.gallery-pill-btn` / `.leaderboard-sort-btn` / `.back-link`** — матова темна пігулка (`--pill-bg` + `backdrop-filter: blur`), використовується для другорядних дій над фоновим зображенням.

### Навігація (`SiteHeader.tsx`)

- Плаваюча плашка `.menutext`: `Головна · Приєднатися · Вікі · Мапа · Інше ⌄`.
- **«Інше»** — випадний список (клік, не hover) для другорядних розділів (`Таблиця лідерів`, `Галерея`), щоб не роздувати плашку окремими іконками щоразу, як додається новий розділ. Патерн: кнопка з `.nav-more-arrow`, що обертається на 180° при відкритті, панель `.nav-more-dropdown` прикріплена до правого краю кнопки (не центрована — вона остання в рядку).
- **Мобільне меню** (`.mobile-menu`) показує ті самі пункти пласким списком — там вистачає вертикального простору, не треба згортати їх у дропдаун.
- Будь-який новий випадний список — **тільки клік** (`onClick` toggle + click-outside), ніколи `onMouseEnter`/`onMouseLeave`. Hover не має еквівалента на дотик — саме це ламало меню профілю на мобільних (виправлено).
- Герой (`.header-img`, 100vh) показується на всіх сторінках, крім перелічених у `isSlimHeader` (профіль, адмінка, лідерборд, галерея, вікі, `/auth/error`, мапа, `/shop`+`/shop/sponsorship/*`). Слот показує `logo.png` за замовчуванням, `join.png` на `/join`, `404.png` на сторінках 404 (через проп `heroImage="404"`).

### Панелі/картки

Стандартний рецепт великої картки: `background: var(--panel-bg); border: var(--panel-border); border-radius: var(--panel-radius);`. Рядок-елемент усередині такої картки (таблиця лідерів, список у адмінці) — `var(--panel-row-bg)` + `var(--panel-row-border)`, не `--panel-bg` (бо на прозорому фоні його майже не видно).

### Сторінка 404

Дві незалежні реалізації (обидві показують `404.png` у справжньому геро-слоті хедера, не мініатюрний банер):

1. `app/global-not-found.tsx` — для *будь-якого* неіснуючого URL (Next вирішує це до зіставлення з жодним маршрутом, тому файл сам несе `<html>`/шрифти/хедер/футер).
2. `app/(site)/not-found.tsx` — для явного виклику `notFound()` усередині вже знайденого маршруту (наприклад, неіснуюча стаття вікі); рендериться всередині звичайного `(site)/layout.tsx`.

## Принципи, які варто зберігати

1. **Один токен — одне значення.** Перш ніж писати новий літеральний колір, перевір, чи немає вже відповідного `--text-*`/`--panel-*`/`--pill-*` токена.
2. **Фон і текст рухаються разом.** Якщо фон елемента токен-залежний (`var(--panel-bg)`, `var(--pill-bg)`) — текст теж має бути токеном. Якщо фон — фіксований літерал (втоплене поле, дропдаун, модалка) — текст теж лишай літералом. Змішування (токен-текст на літерал-фоні або навпаки) — найчастіша причина «тексту, який не видно».
3. **Специфічність замість порядку файлу.** Коли новий селектор має перебити наявне компаундне правило (наприклад, `.menutext a`), додавай клас+клас+елемент (`.nav-more .nav-more-dropdown a`), а не сподівайся на порядок у файлі — рівна специфічність програє мовчки, якщо хтось пізніше переставить блоки.
4. **Вимірюй, не вгадуй.** Позиціонування (надто зі flex/grid) краще перевіряти реальними `getBoundingClientRect()`/скриншотами, а не читанням CSS — авто-марджини у flex-контейнері, конфлікти специфічності й подібне регулярно дають несподіваний результат, який на папері виглядав правильно.
